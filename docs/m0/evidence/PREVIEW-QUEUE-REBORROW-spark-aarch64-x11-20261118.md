# Preview queue re-borrow regression — spark X11

The release app panicked with `RefCell already borrowed` at `workspace.rs:125` after submitting a second long preview while the first was active. The [pre-fix backtrace](preview-queue-reborrow-spark-x11-20261118/repro-backtrace.log) captures the panic; the first click in the initial attempt only focused the window, and a Results tab switch by itself was not established as the trigger.

The result and failure handlers kept the `RefMut` from an `if let` scrutinee alive while invoking the next dispatch, which re-borrowed the same map. They now remove the pending entry before invoking the callback. The focused `removed_pending_callback_can_dispatch_and_reborrow_map` unit test failed with `BorrowMutError` when the callback deliberately ran while retaining the mutable borrow, and passed after releasing it. `cargo test --locked --workspace` also passed on Rust 1.100.0 with `PKG_CONFIG_PATH=/tmp/gtkdev/pc`.

In a live Xvfb X11 run of the equivalent initial fix, [preview 1](preview-queue-reborrow-spark-x11-20261118/fixed-nohud-running1.png) advanced to [preview 2](preview-queue-reborrow-spark-x11-20261118/fixed-nohud-running2.png) after another submission; the [application log](preview-queue-reborrow-spark-x11-20261118/fixed-nohud.log) contains no panic. After a Results/SQL tab switch and killing its worker, the app displayed [generation 2 and resumed progress](preview-queue-reborrow-spark-x11-20261118/fixed-generation2.png). The callback helper and regression test were added subsequently. A fresh live run of the final release binary again advanced to preview 2 and survived a worker restart; see [N7 v2 evidence](N7-v2-spark-aarch64-x11-20261118.md).
