# N5 no-portal and picker-error fallback on spark-aarch64/X11 — 2026-11-18

- Host: lizhan-spark, Ubuntu 24.04, Linux aarch64; GTK4 `4.14.5`; isolated X11/Xvfb `:105`, 1600×1000×24.
- Runtime: NSH `0.5.1`; DuckDB `v2.0.0`; duckomo `v0.4.0`, GitHub-release-unsigned, `linux_arm64`.
- Validation build: `RUSTUP_TOOLCHAIN=1.100.0 PKG_CONFIG_PATH=/tmp/gtkdev/pc cargo build -p omo-app --release --locked --features dialog-test-seams` passed. App SHA-256: `095dac6e0cdba7ce14d92b131a9f8b40252ceafc7b23d1b2809c462a116aeccc`.

## No portal service

Launched the app with `GTK_USE_PORTAL=1` on an isolated private D-Bus session using [session-no-activation.conf](n5-spark-aarch64-x11-20261118/session-no-activation.conf), which omits D-Bus service activation directories. The GTK4 file chooser opened through the local GTK implementation without a portal service. The station CSV open dialog was cancelled and returned to “No station CSV selected.” See [workbench](n5-spark-aarch64-x11-20261118/no-portal-workbench.png), [open dialog](n5-spark-aarch64-x11-20261118/no-portal-open-dialog.png), and [cancelled open](n5-spark-aarch64-x11-20261118/no-portal-cancelled.png).

A default `SELECT 1` preview completed with one row. The export action opened a save dialog with default filename `omobench-results.csv` and CSV/Parquet filters. Cancelling returned to the workbench with the preview intact and without starting an export. See [result ready](n5-spark-aarch64-x11-20261118/result-ready.png), [save dialog](n5-spark-aarch64-x11-20261118/no-portal-save-dialog.png), and [cancelled save](n5-spark-aarch64-x11-20261118/no-portal-save-cancelled.png). The successful no-portal app log is [here](n5-spark-aarch64-x11-20261118/no-portal-app.log).

## Picker-error callback and manual path

The validation-only `dialog-test-seams` feature and `OMOBENCH_TEST_PORTAL_ERROR=1` route the station-picker action through the same application error callback used when `pick_paths` returns an error. The UI showed “File chooser unavailable (simulated portal failure: no file chooser service). Enter a path below.” I entered `/home/blizhan/repo/github/OmO/fixtures/stations/m0.csv` and selected “Use path”; the UI reported “Path saved in this window only; CSV ingestion is not connected yet.” See [injected error](n5-spark-aarch64-x11-20261118/simulated-picker-error.png) and [accepted manual path](n5-spark-aarch64-x11-20261118/manual-path-accepted.png). The seam log is [here](n5-spark-aarch64-x11-20261118/error-seam-app.log).

This injects an error at the picker/application boundary; it does not emulate portal D-Bus protocol messages. The no-service run verifies GTK's local chooser behavior, while the injected error verifies the application's manual-path fallback. Earlier spark X11 evidence covers open and save cancellation with portal services available and manual path entry: [N5 2026-11-17](N5-spark-aarch64-x11-20261117.md).

Result: the spark X11 N5 open/save flows pass with and without portal services, and the simulated picker-error branch exposes and accepts a manual path. Nested Weston Wayland controls remain unverified; Linux x86_64 and macOS N5 runs remain not-run. This evidence does not close those cells.
