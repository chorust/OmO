# Gate `S0-NSH-070` — nsh `=0.7.0` Spark X11 GUI smoke — **FAILED, bump reverted to `=0.5.1`** — 2026-11-26

- Host `lizhan-spark` (`aarch64`), Xvfb `1600x1000x24` + openbox (`/tmp/omo-x11/root`), same bootstrap config, same harness
  start-up (`scripts/automate_m1_gui.py` first step: locate the `Omobench Studio` window).
- Both binaries are release builds: baseline = detached checkout of `6ce7889` (nsh `=0.5.1`), candidate = M2 branch with nsh `=0.7.0`.
- Probe: start app, poll `xdotool search --name Omobench` every 5 s for 30 s, then `xwd` screenshot.

| build | windows after 30 s | screenshot |
|---|---|---|
| nsh `=0.5.1` (baseline) | `com.omobench.studio` 1x1 **and** `Untitled project ● [draft staged] — Omobench Studio` `1440x960` | `S0-baseline-0.5.1-window.png` (UI rendered) |
| nsh `=0.7.0` | only `com.omobench.studio` `1x1`; the main window is **never created/mapped** | `S0-nsh-0.7.0-no-window.png` (empty desktop) |

Retried with `GSK_RENDERER=cairo` and `GDK_BACKEND=x11 GSK_RENDERER=gl`: same result for `0.7.0`. App log only has libEGL DRI3
warnings and nsh class warnings (no panic). The baseline works in the identical environment, so this is a `0.7.0` regression
on Spark/X11, not an Xvfb problem.

## Decision

`tasks.md` T002: "STOP and revert `T001`'s NSH bump to `=0.5.1` if any existing GUI workflow regresses." Reverted:
`Cargo.toml`, `crates/omo-app/Cargo.toml`, `scripts/check-boundaries.sh` pins → `=0.5.1`; `Cargo.lock` restored from `HEAD` and
re-resolved only for the new `omo-engine` dependencies; Constitution `1.4.0` proposal withdrawn (file restored, stays `1.3.0`).
