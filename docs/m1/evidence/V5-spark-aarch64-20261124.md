## Verified Scenarios

### 1. Automatic Draft Scheduler & Crash Recovery
- **Action**: App runs with confirmed stations and received series result. The draft scheduler writes periodic snapshots to `~/.local/share/omobench/drafts/<doc-id>.json`.
- **Crash/Restart**: On subsequent startup, `project.offer_recovery()` inspects the drafts folder.
- **Observed**: A centered modal alert dialog appears over the workbench:
  - Title: `Recover unsaved project?`
  - Message: `An unsaved draft from 2026-11-24T04:01:05Z was found.`
  - Actions: `[ Restore ]` and `[ Discard ]`
- **Action**: Click `Restore`.
- **Observed**: The 100 stations and project state are restored into the UI (`100 stations confirmed · .../fixtures/stations/m1-100.csv`), and status bar displays:
  `Recovered the unsaved draft.`
- **Evidence**: `docs/m1/evidence/V5-01-recovery-dialog.png` and `/tmp/restored_fixed.png`

### 2. Window Close Guard Interception (R-07)
- **Action**: Window has uncommitted changes (`is_dirty() == true`). Send window close request (`WM_DELETE_WINDOW` / Alt+F4 / `xdotool windowclose`).
- **Observed**: Window close is intercepted via `close_on_press = Some(false)` and `main_window().on_close_press(...)`.
- **Modal Dialog**: `alert_dialog()` prompts:
  `Save changes to this project?` with `Save`, `Discard`, `Cancel`.
  Clicking Cancel preserves project state without exiting.
