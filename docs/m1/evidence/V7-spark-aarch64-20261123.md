# V7 — Fault injection (SC-005) — 2026-11-23

- **Host**: `lizhan-spark` (`aarch64-unknown-linux-gnu`), 2026-11-23 UTC
- **Versions**: Rust `1.100.0`, DuckDB `v2.0.0`, duckomo `v0.4.0`, debug `omo-worker`
- **Harness**: `scripts/fault-inject-series.py --trials 10` (real worker, real network, 100-station `series`, default window), using `scripts/omo_worker_client.py`.

## Results (10 trials each)

| Fault | Expected | Result |
|---|---|---|
| Cancel during reading | `failed` with `Cancelled`; worker still answers `catalog_check` | **10/10** |
| `kill -9` of the worker during reading | worker process dies (EOF); a generation-2 worker completes a retry | **10/10** |
| Network unavailable before the request (`no_network`) | `catalog_check` → `NotReady(RemoteUnavailable)`; `series` → `CapabilityUnavailable(remote)` | **10/10** |
| Network down during reading | failed request; last result kept stale | **not run** (see below) |

## Defect found and fixed

The first cancel trials were not reliable: in one of three trials the interrupt was ignored and the 100-station `series` ran to completion (95 s) and returned a `result` instead of `Cancelled`.
Cause: the worker's interrupt handle only covered the main DuckDB connection, while Plan G reads on up to 20 per-worker connections.
Fix: `omo_engine::series::SeriesCancel` (flag plus interrupt handles registered by each Plan G reader connection, flag checked between point reads and before the write stage), wired through `EngineBackend::cancellation()` in `crates/omo-worker/src/main.rs`; unit test `series_cancel_flag_is_checked_and_reset_between_requests`.
The 10/10 cancel result above was measured after the fix.

## Caveats

- An earlier `kill9` run completed trials 0–8 and then crashed the script because the trial-9 `series` request failed before `reading` (error text not captured by that version of the script). The script now records such a trial as a failure with the worker's message; a full rerun passed 10/10, and the failure did not recur.
- Kill and cancel are checked at worker-protocol level. `WorkerCrashed` classification, the generation increment, "previous result kept", and "UI idle" are supervisor/UI behaviours covered by `crates/omo-app/tests/supervisor.rs` and M0 evidence, not re-observed here through the GUI.
- Network-down-during-reading needs a way to cut the network mid-request (root firewall or a network namespace toggle). This host account has no passwordless sudo, so the row remains unverified.
